# Content — Empty state

Wording for an empty content area. For *when* to use an Empty State vs another surface, and its variants, see `reference/patterns/feedback-states.md`; for the component, `reference/components/empty-state.md`.

## Structure
Use the **same three-part structure as an error message** (`error-message.md`): Observation → Cause (when clear) → Solution.

## Guidelines
There are no strict rules here — be a little creative, within these:
- **Reassure the user they're not in the wrong.** An empty area is usually normal, not a failure.
- **Convey service** — show you tried: "Het lukt ons niet om…" gives a sense of effort on the user's behalf.
- **A small branded joke is allowed**, as long as it never gets in the way of helping — e.g. "NS Flex beweegt even niet mee."

> Tone still follows the variant: the *error*/*offline* readings stay plain (no jokes when money or a journey is involved); *empty*/*all-clear* can be lighter. See `feedback-states.md → Tone`.
